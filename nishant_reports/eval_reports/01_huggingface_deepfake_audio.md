## Dataset

**Source:** [garystafford/deepfake-audio-detection](https://huggingface.co/datasets/garystafford/deepfake-audio-detection) on HuggingFace

We randomly sampled 200 files (100 real, 100 fake) from this 1,866-file dataset. Audio is 16kHz mono FLAC, 2.5-13 seconds per clip.

- **Real audio:** Sourced from 14 YouTube recordings of natural human speech
- **Fake audio:** Generated by 6 modern TTS engines — ElevenLabs, Speechify, Amazon Polly, Hume AI, Hexgrad Kokoro, and Luvvoice

This dataset was chosen because none of these TTS engines appear in our training data (which used RitW, ASVspoof 2021 LA, MLAAD, CVoiceFake, ASVspoof5). This tests out-of-distribution generalization.

## Methodology

We ran all three detection engines on the same 200 files:

1. **ML Engine** — Frozen Wav2Vec2-large-960h + linear head, threshold 0.55
2. **Physics Engine** — Deterministic acoustic analysis (jitter/shimmer, formant velocity, HNR, temporal consistency, spectral flux). Flags FAKE if >= 2 of 7 checks fail
3. **Combined Engine** — AND logic: FAKE only if both ML and physics agree

## Results

| Engine | Accuracy | FPR | FNR |
|--------|----------|-----|-----|
| ML Engine (v1.2.4) | 29.0% | 43.0% | 99.0% |
| **Physics Engine** | **70.0%** | **11.0%** | **49.0%** |
| Combined (AND) | 48.5% | 3.0% | 100.0% |

### ML Engine

The ML engine effectively failed on this dataset. Fake audio scored an average of 0.22 (should be high), while real audio scored 0.51 (essentially random). Only 1 out of 100 fake files was correctly flagged. The model does not generalize to these newer TTS generators.

### Physics Engine

The physics engine was the best performer at 70% accuracy. It detected 51/100 fakes while only falsely flagging 11/100 real files.

Checks-failed distribution:

| Checks failed | Fake files | Real files |
|---------------|------------|------------|
| 0 | 10 | 49 |
| 1 | 39 | 40 |
| 2 (flagged) | 41 | 10 |
| 3 (flagged) | 9 | 1 |
| 4 (flagged) | 1 | 0 |

49 fake files failed only 0-1 checks, narrowly avoiding detection. The current threshold of >= 2 checks is conservative.

### Combined Engine

The AND logic makes the combined engine strictly more conservative than either engine alone. Because the ML engine missed 99% of fakes, the combined engine caught zero fakes. The low 3% FPR is meaningless when FNR is 100%.

## Recommendations

1. **Retrain the ML model on modern TTS engines.** The current training data predates ElevenLabs, Speechify, and similar commercial TTS services. Adding samples from these generators (or similar ones like OpenAI TTS, Google Cloud TTS, Bark) to the training mix would likely recover ML performance on this class of fakes.

2. **Consider lowering the physics engine threshold to >= 1 check failed.** 39 fake files failed exactly 1 check. Lowering the threshold from 2 to 1 would catch 90/100 fakes, but at the cost of raising FPR from 11% to 52%. A middle ground could be a weighted scoring system rather than a binary check count — where some checks (e.g., jitter/shimmer) contribute more to the verdict than others.

3. **Switch the combined engine from AND to OR logic (or weighted voting).** AND logic is too conservative — one weak engine vetoes the other. An OR or weighted-majority approach would let the physics engine carry the verdict when the ML engine is uncertain (scores near 0.5) and vice versa.

4. **Use ML confidence to gate the combined decision.** When the ML score is near 0.5 (uncertain), defer to the physics engine alone. When the ML score is extreme (>0.9 or <0.1), trust it. This avoids the binary AND/OR tradeoff.

5. **Fine-tune the top Wav2Vec2 layers on a broader TTS mix.** The v1.2.4 model already fine-tunes encoder layers 23-24. Expanding the fine-tuning dataset with modern TTS samples while keeping the same architecture could improve generalization without a full retrain.
